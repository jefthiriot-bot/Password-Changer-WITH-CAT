# Windows 11 verification still required

These are real integration checks, not a demo mode. Use a disposable local account first and keep a separate administrator session available. No Windows machine was available during the macOS build.

1. Open the executable. Verify UAC, automatic installation, both shortcuts, and app-password setup. Close and reopen; verify the app password is required. Reject an incorrect app password, change it using the old one, and verify the old one no longer unlocks.
2. Confirm only eligible local accounts appear. Select the disposable account and a four-digit math password. Supply its correct current password, then change it. Confirm the displayed password is the answer to the displayed clue.
3. Use Switch user, select Password sign-in, check the visible hint after a wrong password, and successfully sign in with the generated answer. Do not repeatedly submit wrong passwords; account lockout policy may apply. This is the essential test of the undocumented hint mechanism.
4. Repeat with a word riddle. Enter the one-word lowercase answer. Test a custom hint and Update hint only; confirm the password itself does not change. Restore automatic clues and check that updating only the hint matches the existing password.
5. Set a short interval appropriate to your Windows minimum-password-age policy. Close the app. Check that the task runs as SYSTEM and changes the password. Reopen and verify the last-change time, password, and hint. Verify a second account is not changed unless configured.
6. Pause. Wait longer than the interval and verify no change. Resume and verify the next due time. Restart or sleep through a due time and verify one catch-up change, not multiple rapid changes.
7. Use PANIC. Confirm the selected account is reset to the configured emergency password, its schedule is paused, and its old riddle is gone. If password policy rejects the emergency password, confirm a visible error and no false success.
   Also close the main app and open `PasswordPuzzle-Reset.exe`. Verify it requires the same app password, lists only configured eligible accounts, and completes the same emergency reset using the installed worker. Verify launching it before main-app setup displays setup instructions and does not change accounts.
8. Verify the app window remains usable at 100%, 150%, and 200% display scaling, scrolling when necessary. Check Reveal hides again after 15 seconds and the app locks after five idle minutes.
9. As a non-administrator, verify the vault directory cannot be read or edited and the task cannot be modified. Inspect the task: installed executable only, SYSTEM, every minute plus boot trigger, runs on battery, no network dependency.
10. Inspect any policy rejection: the old password and hint should remain valid, the account should pause, and the latest-password field should not display an uncommitted candidate.
11. Click **Type a password...**, enter and confirm a custom password for the disposable account, and add a hint. Verify the exact typed password signs in, the hint changes, and automatic changes pause. Repeat with an empty hint to clear the previous clue. Mismatched confirmation must not queue a change. Switching accounts or locking the app must clear the typed fields.
12. Verify the XP-inspired blue headers, cream panels, and beveled buttons render in both EXEs, including hover, pressed, keyboard focus, and disabled states. **Created by @Jef_Dawg** must remain visible while scrolling. Windows 11 still supplies the outer window frame.
13. Switch through all six themes in each app. Check text fields, drop-down lists, checkboxes, group headings, warning messages, buttons, and the footer for readability. Verify selection and focus indicators in High Contrast using only the keyboard. Close and reopen both apps and check that the selected theme survives. With both apps open, a theme change should appear in the other within a few seconds.
14. Select Cat. Verify the supplied cat image appears without cropping or stretching and requires no PNG beside the EXE. Check the main and reset forms remain scrollable at high display scaling. Switching away from Cat should remove its panel. Confirm that the same account remains selected, typed input remains unchanged, and no password change or schedule change is triggered by changing themes.

Test fault injection and forced interruption only in a disposable VM. Check that a password candidate remains recoverable after interruption, failed hint writes pause rotation, and Repair hint does not reset the password. Do not kill a real account operation merely to test this.

15. Open **All account passwords** and verify it asks for the app password again. Confirm that unmanaged and disabled local accounts are listed without guessed passwords, recorded passwords match their most recent successful app changes, and unresolved operations show Uncertain. Reveal all, wait 15 seconds, and switch windows to check automatic hiding. Verify the window closes after five minutes and does not change any account. Check the table in each theme and at high display scaling.
